# 獨立對象紀錄

一筆 record 表達一個可辨識的收錄對象及其適用範圍。人物、不同品牌、不同商品 SKU 各有獨立紀錄；同一人的本名、藝名、英文名及繁簡變體，或同一品牌的名稱變體仍放 aliases。品牌及其單一營運公司的名稱橋接可留同筆，不因名稱不同便自動視為另一個避開對象。

```text
來源檔
|-- 單一對象 record()
`-- 共用背景 splitRecord()
    |-- 明列成員 A：自己的名稱、別名、識別、摘要
    `-- 明列成員 B：自己的名稱、別名、識別、摘要
        |
        v
    compileRecords()
        |
        v
    獨立完整 JSON / HTML -> 名稱目錄與查詢索引
```

`splitRecord(group, members)` 只是來源去重工具，不是新的編譯入口或公開群組格式。展開後的紀錄與普通 record 相同，原群組不另輸出；外部 reader 不需懂群組或另抓一份名冊。

- 成員必須明列 `name` 與限自身的 `summary`；不能由 aliases 自動猜成員、按斜線切名字或依姓名碰撞合併。
- 成員 `aliases`、`identifiers` 預設空，絕不繼承整組查詢鍵。相同人物的名稱變體須明確分配給該人。
- `id` 可明示；否則由原群組 ID 與成員名稱的 Unicode code points 組成，不依名冊順序。改名時應明示既有 ID，避免不必要的 ID 變動。
- 其他共同欄位沿用 group；異質的 `sources`、`avoidReasons`、`country`、`status`、`confidence`、`aiNotes`、期限等須逐成員覆寫。共用來源不等於每位都發表同一言論、負有同一責任、受同一制裁或有同一罪名。
- 歷史查核日期、觀察中／個人避開、特定區域授權、少數持股／待完成交易及 SKU／批號限制均須保留。只整理資料不重設 `lastReviewed`。
- 遷移原 ID 前檢查 record-overrides 是否遮蔽來源；不得另建一份子紀錄覆寫表或以舊產物補資料。

完成後依 AGENTS 的完整 gate 驗證，並補名稱／別名／識別正查及其他成員、母品牌、事件理由詞等範圍負查。目錄與索引必須能直接到達每筆完整紀錄，不把同一別名數量當成新增人物數。
